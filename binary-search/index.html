Binary Search

Binary search finds a value in a sorted array by repeatedly comparing with the middle element and discarding the half that cannot contain the target. Each step halves the remaining work.

  • Level: Beginner
  • Read time: 8 min
  • Time: O(log n)
  • Requires: Sorted data

The idea

You are looking for a word in a printed dictionary. You do not start at page one. You open near the middle, see whether your word comes before or after that page, and ignore the other half. Then you repeat on what is left. That is binary search.

It keeps two boundaries, lo and hi, around the part of the array that could still contain the target:

  1. Look at the middle element, mid.
  2. If it is the target, stop.
  3. If it is smaller than the target, the target must be to the right: set lo = mid + 1.
  4. If it is larger, the target must be to the left: set hi = mid − 1.
  5. Repeat until found or until lo passes hi.

Try it: watch the range shrink

Search for a value in the array, then for one that is not there. Count the steps.

Why it is O(log n)

Every comparison halves the candidates. Starting from n, after k steps n / 2k remain; the search ends when that reaches 1, so k = log₂ n.

The requirement is that the data is sorted and supports random access. On unsorted data the comparison with the middle tells you nothing about which half to discard, and on a linked list reaching the middle is itself O(n).

Three details that cause most bugs

  • The loop condition. With an inclusive range [lo, hi] use while lo <= hi. With < you skip the case of one remaining element.
  • Moving the boundaries. Use mid + 1 and mid − 1. Setting lo = mid can loop forever when two elements are left.
  • Computing the middle. In languages with fixed-size integers, (lo + hi) / 2 can overflow for very large arrays. Write lo + (hi − lo) / 2.

Lower bound: binary search beyond exact match

A more general version finds the first position whose value is at least the target. It answers "where would this value be inserted?", locates the first occurrence among duplicates, and is the form behind Python's bisect_left. It uses a half-open range [lo, hi) and never returns early; see lower_bound in the code below.

The same halving idea works on any monotonic condition: one that is false up to some point and true afterwards. "What is the smallest capacity that ships all packages within D days?" has no array in it, yet it is solved by binary search over the possible answers.

Binary Search in Python, Java and JavaScript

Every sample below runs as is and prints the results shown in its comments. Switch language with the tabs; your choice is remembered on every page.

import bisect


def binary_search(items, target):         # O(log n); items must be sorted
    lo, hi = 0, len(items) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            lo = mid + 1                  # target is in the right half
        else:
            hi = mid - 1                  # target is in the left half
    return -1


def lower_bound(items, target):
    """First index whose value is >= target (the insertion point)."""
    lo, hi = 0, len(items)                # note: hi is one past the end
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if items[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo


nums = [3, 8, 15, 15, 15, 23, 42, 57]
print(binary_search(nums, 23))            # 5
print(binary_search(nums, 9))             # -1
print(lower_bound(nums, 15))              # 2  (first 15)
print(bisect.bisect_left(nums, 15))       # 2  (standard library equivalent)
import java.util.Arrays;

public class BinarySearch {
    static int binarySearch(int[] items, int target) {     // O(log n); items must be sorted
        int lo = 0, hi = items.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;                  // avoids int overflow of (lo + hi)
            if (items[mid] == target) return mid;
            if (items[mid] < target) lo = mid + 1;         // target is in the right half
            else hi = mid - 1;                             // target is in the left half
        }
        return -1;
    }

    /** First index whose value is >= target (the insertion point). */
    static int lowerBound(int[] items, int target) {
        int lo = 0, hi = items.length;                     // note: hi is one past the end
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (items[mid] < target) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }

    public static void main(String[] args) {
        int[] nums = {3, 8, 15, 15, 15, 23, 42, 57};
        System.out.println(binarySearch(nums, 23));        // 5
        System.out.println(binarySearch(nums, 9));         // -1
        System.out.println(lowerBound(nums, 15));          // 2  (first 15)
        System.out.println(Arrays.binarySearch(nums, 42)); // 6  (standard library)
    }
}
function binarySearch(items, target) {     // O(log n); items must be sorted
  let lo = 0, hi = items.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (items[mid] === target) return mid;
    if (items[mid] < target) lo = mid + 1; // target is in the right half
    else hi = mid - 1;                     // target is in the left half
  }
  return -1;
}

  return lo;
}

When to use it

Use binary search when

  • The data is sorted and stored in an array.
  • You search the same data many times.
  • The answer lies in a numeric range and you can test whether a guess is too low or too high.

Look elsewhere when

  • The data is unsorted and searched only once (a linear scan is cheaper than sorting first).
  • The data changes constantly (use a balanced tree or a hash table).

Common mistakes

  • Running it on unsorted data. It returns wrong answers silently.
  • while lo < hi with an inclusive hi, missing the last candidate.
  • lo = mid instead of lo = mid + 1, causing an infinite loop.
  • Integer overflow in (lo + hi) / 2 in Java, C or C++.
  • Expecting the first occurrence when duplicates exist. Plain binary search returns any match; use lower bound.

Binary search over the answer with a feasibility check that is monotonic.

Frequently asked questions

Does binary search work on unsorted arrays?

No. It depends on knowing that everything left of the middle is smaller and everything right is larger. On unsorted data use a linear scan, or sort first if you will search many times.

What is the time complexity of binary search?

O(log n) time and O(1) extra space for the iterative version. A million sorted items need at most about 20 comparisons.

Why write lo + (hi - lo) / 2 instead of (lo + hi) / 2?

Both give the same middle, but lo + hi can exceed the maximum value of a fixed-size integer for very large arrays. The first form cannot overflow.
