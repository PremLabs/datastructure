Hash Tables

A hash table stores key–value pairs and finds a value from its key in constant time on average. It does this by running the key through a hash function that says which slot of an array to use.

  • Level: Intermediate
  • Read time: 11 min
  • Lookup: O(1) average
  • Worst case: O(n)

What is a hash table?

An array gives O(1) access, but only if you know the index. A hash table extends that speed to any kind of key: a name, an email address, a product ID. It needs two parts:

  1. An array of buckets.
  2. A hash function that turns a key into a number. That number, modulo the number of buckets, is the bucket index.

To store "cat" → 3, hash "cat", go to that bucket and put the pair there. To read it back, hash "cat" again. The same key always produces the same index, so you go directly to the right bucket without looking at any other. Dictionaries in Python, HashMap in Java, and Map and plain objects in JavaScript are all hash tables.

Try it: hashing and collisions

This demo uses a deliberately simple hash (add up the character codes) with 7 buckets, so collisions are easy to produce. Put the key tac and see where it lands.

Collisions

There are far more possible keys than buckets, so two different keys will sometimes produce the same index. This is a collision, and handling it is the heart of hash table design.

Separate chaining

Each bucket holds a small list of entries. Colliding keys simply share the bucket, and a lookup scans that short list comparing keys. This is what the visualizer and the code below use. Java's HashMap uses chaining and converts long chains into balanced trees.

Open addressing

Every entry lives in the array itself. If the target slot is taken, probe the next slots according to a fixed rule (linear probing checks the next slot, then the next) until a free one is found. Python's dict uses open addressing. It is more cache-friendly but deletion is trickier, needing a marker for removed entries.

Load factor and resizing

The load factor is entries ÷ buckets. As it rises, chains lengthen and lookups slow down. When it passes a threshold (0.75 is common) the table allocates a bigger array, usually double, and rehashes every entry into it, because the bucket index depends on the array size. Rehashing is O(n) but rare, so insertion remains O(1) amortised, the same argument as for dynamic arrays.

What makes a good hash function

  • Deterministic: the same key always gives the same hash.
  • Uniform: keys spread evenly over the buckets. The character-sum hash in the demo is poor precisely because anagrams collide.
  • Fast: it runs on every operation.

You rarely write one yourself, but you must respect one rule: keys must not change while they are in the table. If a key's hash changes after insertion it sits in the wrong bucket and can no longer be found. This is why Python allows only immutable objects as dictionary keys, and why Java requires equals and hashCode to be overridden together.

Hash Tables in Python, Java and JavaScript

class HashTable:
    """Hash table with separate chaining and automatic resizing."""

    def __init__(self, capacity=8):
        self._buckets = [[] for _ in range(capacity)]
        self._size = 0

    def _index(self, key):
        return hash(key) % len(self._buckets)

    def put(self, key, value):            # O(1) average
        bucket = self._buckets[self._index(key)]
        for pair in bucket:
            if pair[0] == key:
                pair[1] = value           # key exists: overwrite
                return
        bucket.append([key, value])
        self._size += 1
        if self._size > 0.75 * len(self._buckets):   # load factor too high
            self._resize()

    def get(self, key, default=None):     # O(1) average
        for k, v in self._buckets[self._index(key)]:
            if k == key:
                return v
        return default

    def remove(self, key):                # O(1) average
        bucket = self._buckets[self._index(key)]
        for i, (k, _) in enumerate(bucket):
            if k == key:
                del bucket[i]
                self._size -= 1
                return True
        return False

    def _resize(self):                    # O(n): every key is rehashed
        old = self._buckets
        self._buckets = [[] for _ in range(len(old) * 2)]
        self._size = 0
        for bucket in old:
            for k, v in bucket:
                self.put(k, v)

import java.util.ArrayList;
import java.util.List;

public class HashTable<K, V> {
    private static class Entry<K, V> {
        final K key; V value;
        Entry(K key, V value) { this.key = key; this.value = value; }
    }

    private List<List<Entry<K, V>>> buckets = newBuckets(8);
    private int size = 0;

    private static <K, V> List<List<Entry<K, V>>> newBuckets(int n) {
        List<List<Entry<K, V>>> list = new ArrayList<>();
        for (int i = 0; i < n; i++) list.add(new ArrayList<>());
        return list;
    }

    private int index(K key) {
        return Math.floorMod(key.hashCode(), buckets.size());   // floorMod: never negative
    }

    public void put(K key, V value) {                  // O(1) average
        List<Entry<K, V>> bucket = buckets.get(index(key));
        for (Entry<K, V> e : bucket) {
            if (e.key.equals(key)) { e.value = value; return; }
        }
        bucket.add(new Entry<>(key, value));
        if (++size > 0.75 * buckets.size()) resize();
    }

    public V get(K key) {                              // O(1) average
        for (Entry<K, V> e : buckets.get(index(key))) {
            if (e.key.equals(key)) return e.value;
        }
        return null;
    }

    public boolean remove(K key) {                     // O(1) average
        if (buckets.get(index(key)).removeIf(e -> e.key.equals(key))) { size--; return true; }
        return false;
    }

    private void resize() {                            // O(n): every key is rehashed
        List<List<Entry<K, V>>> old = buckets;
        buckets = newBuckets(old.size() * 2);
        size = 0;
        for (List<Entry<K, V>> bucket : old) for (Entry<K, V> e : bucket) put(e.key, e.value);
    }

    public static void main(String[] args) {
        HashTable<String, Integer> table = new HashTable<>();
        for (String word : "the quick brown fox jumps over the lazy dog the end".split(" ")) {
            Integer count = table.get(word);
            table.put(word, count == null ? 1 : count + 1);
        }
        System.out.println(table.get("the") + " " + table.get("fox") + " " + table.get("cat")); // 3 1 null
    }
}
// In real code use Map. This class shows how one works inside.
class HashTable {
  #buckets = Array.from({ length: 8 }, () => []);
  #size = 0;

  #hash(key) {                             // simple string hash
    let h = 0;
    for (const ch of String(key)) h = (h * 31 + ch.charCodeAt(0)) >>> 0;
    return h % this.#buckets.length;
  }

  put(key, value) {                        // O(1) average
    const bucket = this.#buckets[this.#hash(key)];
    const pair = bucket.find(p => p[0] === key);
    if (pair) { pair[1] = value; return; } // key exists: overwrite
    bucket.push([key, value]);
    if (++this.#size > 0.75 * this.#buckets.length) this.#resize();
  }

  get(key) {                               // O(1) average
    const pair = this.#buckets[this.#hash(key)].find(p => p[0] === key);
    return pair ? pair[1] : undefined;
  }

  remove(key) {                            // O(1) average
    const bucket = this.#buckets[this.#hash(key)];
    const i = bucket.findIndex(p => p[0] === key);
    if (i < 0) return false;
    bucket.splice(i, 1);
    this.#size--;
    return true;
  }

  #resize() {                              // O(n): every key is rehashed
    const old = this.#buckets;
    this.#buckets = Array.from({ length: old.length * 2 }, () => []);
    this.#size = 0;
    for (const bucket of old) for (const [k, v] of bucket) this.put(k, v);
  }
}

const table = new HashTable();
for (const word of 'the quick brown fox jumps over the lazy dog the end'.split(' ')) {
  table.put(word, (table.get(word) ?? 0) + 1);
}
console.log(table.get('the'), table.get('fox'), table.get('cat')); // 3 1 undefined

When to use it

Use a hash table when

  • You look things up by key: caches, indexes, configuration.
  • You count occurrences or group items.
  • You need fast membership tests or de-duplication (a hash set).
  • You want to replace a nested loop with a single pass.

Look elsewhere when

  • You need keys in sorted order or range queries (use a balanced search tree).
  • You search by prefix (use a trie).

Common mistakes

  • Using mutable objects as keys and then modifying them.
  • In Java, overriding equals without hashCode, so equal objects land in different buckets.
  • Relying on iteration order where the language does not guarantee it.
  • In JavaScript, using a plain object as a map with untrusted keys such as "__proto__". Use Map.

Interview questions

Classic problems built on this topic, with the approach to each. Try them yourself before opening the hint.

Two Sum: find two numbers that add to a target.

For each number, check whether target − number is already in a hash map; otherwise store the number. O(n).

Group words that are anagrams of each other.

Use the sorted letters of each word as the key and append the word to that key's list.

Find the first non-repeating character in a string.

Count characters in one pass, then scan again for the first with count 1.

Design an LRU cache.

A hash map from key to node plus a doubly linked list ordered by recency gives O(1) get and put.

How does a HashMap handle collisions?

By chaining entries in the same bucket (or probing for another slot) and comparing keys with equals during lookup.

Frequently asked questions

Why is a hash table lookup O(1)?

The hash function computes the bucket index directly from the key, so the table goes straight to one bucket instead of searching. With a good hash and a controlled load factor, each bucket holds only a few entries.

What is a collision in hashing?

Two different keys mapping to the same bucket. It is handled by chaining (keeping a list in each bucket) or open addressing (probing for another free slot).

What is the difference between a hash map and a hash set?

A hash map stores key–value pairs. A hash set stores keys only and answers the question 'is this item present?'.
