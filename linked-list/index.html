Linked Lists

A linked list is a chain of nodes where each node holds a value and a pointer to the next node. It gives up instant access by index in exchange for cheap insertion and removal.

  • Level: Beginner
  • Read time: 10 min
  • Insert at head: O(1)
  • Access: O(n)

What is a linked list?

Think of a treasure hunt. Each clue tells you where the next clue is hidden. You cannot jump to clue number five; you have to follow the chain from the first one. A linked list stores data the same way. Each node contains a value and a reference (next) to the following node. The list itself only remembers the first node, called the head. The last node's next is null.

The nodes can live anywhere in memory. That means adding a node never requires moving the others: you create it and adjust one or two pointers.

Try it: watch the pointers

Add a value at the head, then at the tail. The first is instant; the second has to walk the whole list.

How the operations work

Insert at the head: O(1)

Create a node, point it at the current head, then make it the new head. Two assignments, whatever the list's length.

Insert at the tail: O(n) or O(1)

With only a head pointer you must walk to the end first. Keep an extra tail pointer and appending becomes O(1). Most real implementations do.

Delete: O(1) once you are there

To remove a node you make the previous node point past it. Finding that previous node is the O(n) part. The code below uses a dummy node in front of the head so that deleting the first node is not a special case. This trick removes a whole class of bugs.

Search and access: O(n)

There is no arithmetic that leads to the k-th node. You follow next k times.

Singly, doubly and circular lists

  • Singly linked: each node has next only. Smallest memory use, one-way traversal.
  • Doubly linked: each node also has prev. You can walk backwards and delete a node in O(1) given only a reference to it. Java's LinkedList and the list behind an LRU cache are doubly linked.
  • Circular: the last node points back to the first. Useful for round-robin scheduling.

Linked list or array?

ArrayLinked list
Access k-th elementO(1)O(n)
Insert / delete at frontO(n)O(1)
Insert / delete in middle (position known)O(n)O(1)
Memory per elementJust the valueValue plus one or two pointers
Cache behaviourExcellent (contiguous)Poor (scattered)

In practice arrays win more often than the table suggests, because modern processors are very fast at scanning contiguous memory. Reach for a linked list when you hold references to nodes and need to splice them in and out, as queues, LRU caches and adjacency lists do.

Linked Lists in Python, Java and JavaScript

Every sample below runs as is and prints the results shown in its comments. Switch language with the tabs; your choice is remembered on every page.

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next


class LinkedList:
    def __init__(self):
        self.head = None

    def add_first(self, value):           # O(1)
        self.head = Node(value, self.head)

    def add_last(self, value):            # O(n) without a tail pointer
        node = Node(value)
        if self.head is None:
            self.head = node
            return
        current = self.head
        while current.next:
            current = current.next
        current.next = node

    def remove(self, value):              # O(n) to find, O(1) to unlink
        dummy = Node(None, self.head)     # dummy node removes the head special case
        prev = dummy
        while prev.next and prev.next.value != value:
            prev = prev.next
        if prev.next is None:
            return False
        prev.next = prev.next.next
        self.head = dummy.next
        return True

    def reverse(self):                    # O(n) time, O(1) space
        prev, current = None, self.head
        while current:
            current.next, prev, current = prev, current, current.next
        self.head = prev

    def __iter__(self):
        current = self.head
        while current:
            yield current.value
            current = current.next


items = LinkedList()
for v in (3, 15):
    items.add_last(v)
items.add_first(8)                        # 8 -> 3 -> 15
items.remove(3)                           # 8 -> 15
items.reverse()                           # 15 -> 8
print(list(items))
public class LinkedList {
    private static class Node {
        int value;
        Node next;
        Node(int value, Node next) { this.value = value; this.next = next; }
    }

    private Node head;

    public void addFirst(int value) {              // O(1)
        head = new Node(value, head);
    }

    public void addLast(int value) {               // O(n) without a tail pointer
        Node node = new Node(value, null);
        if (head == null) { head = node; return; }
        Node current = head;
        while (current.next != null) current = current.next;
        current.next = node;
    }

    public boolean remove(int value) {             // O(n) to find, O(1) to unlink
        Node dummy = new Node(0, head);            // removes the head special case
        Node prev = dummy;
        while (prev.next != null && prev.next.value != value) prev = prev.next;
        if (prev.next == null) return false;
        prev.next = prev.next.next;
        head = dummy.next;
        return true;
    }

    public void reverse() {                        // O(n) time, O(1) space
        Node prev = null, current = head;
        while (current != null) {
            Node next = current.next;
            current.next = prev;
            prev = current;
            current = next;
        }
        head = prev;
    }

    @Override public String toString() {
        StringBuilder sb = new StringBuilder();
        for (Node n = head; n != null; n = n.next) sb.append(n.value).append(n.next != null ? " -> " : "");
        return sb.toString();
    }

    public static void main(String[] args) {
        LinkedList items = new LinkedList();
        items.addLast(3); items.addLast(15);
        items.addFirst(8);                         // 8 -> 3 -> 15
        items.remove(3);                           // 8 -> 15
        items.reverse();                           // 15 -> 8
        System.out.println(items);
    }
}
class Node {
  constructor(value, next = null) {
    this.value = value;
    this.next = next;
  }
}

class LinkedList {
  head = null;

  addFirst(value) {                        // O(1)
    this.head = new Node(value, this.head);
  }

  addLast(value) {                         // O(n) without a tail pointer
    const node = new Node(value);
    if (!this.head) { this.head = node; return; }
    let current = this.head;
    while (current.next) current = current.next;
    current.next = node;
  }

  remove(value) {                          // O(n) to find, O(1) to unlink
    const dummy = new Node(null, this.head); // removes the head special case
    let prev = dummy;
    while (prev.next && prev.next.value !== value) prev = prev.next;
    if (!prev.next) return false;
    prev.next = prev.next.next;
    this.head = dummy.next;
    return true;
  }

  reverse() {                              // O(n) time, O(1) space
    let prev = null, current = this.head;
    while (current) {
      [current.next, prev, current] = [prev, current, current.next];
    }
    this.head = prev;
  }

  *[Symbol.iterator]() {
    for (let n = this.head; n; n = n.next) yield n.value;
  }
}

const items = new LinkedList();

items.addFirst(8);                         // 8 -> 3 -> 15
items.remove(3);                           // 8 -> 15
items.reverse();                           // 15 -> 8

When to use it

Use a linked list when

  • You add and remove at the ends or at known positions far more than you index.
  • You are implementing a queue, deque or LRU cache.
  • You cannot afford the occasional O(n) resize of a dynamic array.

Look elsewhere when

  • You need random access or binary search (use an array).
  • Memory is tight: pointers can double the size of small elements.

Common mistakes

  • Losing the rest of the list by overwriting next before saving it. When reversing, store current.next first.
  • Forgetting the empty list and single-node cases.
  • Not updating head (or tail) when the first (or last) node is removed.
  • Dereferencing null: always check node before reading node.next.

Interview questions

Classic problems built on this topic, with the approach to each. Try them yourself before opening the hint.

Reverse a linked list.

Walk the list with three pointers (previous, current, next), flipping each next to point backwards. O(n) time, O(1) space. It is in the code above.

Detect a cycle.

Floyd's algorithm: move one pointer one step and another two steps at a time. If they ever meet there is a cycle.

Find the middle node in one pass.

Same slow and fast pointers: when the fast one reaches the end, the slow one is in the middle.

Merge two sorted lists.

Use a dummy head and repeatedly attach the smaller of the two front nodes.

Remove the n-th node from the end.

Advance one pointer n steps, then move both until the first reaches the end.

Frequently asked questions

When is a linked list better than an array?

When you frequently insert or remove items at the front or at positions you already hold a reference to. Those operations are O(1) in a linked list and O(n) in an array.

Why is searching a linked list O(n) even if it is sorted?

Binary search needs to jump to the middle element in constant time. A linked list can only reach the middle by walking there, so the advantage disappears.

What is a dummy (sentinel) node?

An extra node placed before the real head. It guarantees every real node has a predecessor, which removes the special-case code for inserting or deleting at the head.
