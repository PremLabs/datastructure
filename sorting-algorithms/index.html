Sorting Algorithms

Sorting puts items in order, and it is the gateway to faster algorithms: binary search, duplicate detection and merging all start from sorted data. These five algorithms cover the ideas every other sort is built from.

  • Level: Beginner to intermediate
  • Read time: 14 min
  • Algorithms: 5
  • Best general: O(n log n)

A sort is stable if items that compare equal keep their original relative order. It matters when you sort records by one field after another: sort by name, then stably by department, and names stay alphabetical within each department.

Bubble sort

Walk through the array comparing each pair of neighbours and swapping them if they are out of order. After one pass the largest value has "bubbled" to the end. Repeat for the rest. If a pass makes no swaps the array is sorted and you can stop, which gives the O(n) best case. It is simple to understand and almost never the right choice in practice.

Selection sort

Find the smallest value in the unsorted part and swap it into the first unsorted position. Repeat. It always does about n²/2 comparisons, even on sorted input, but makes at most n − 1 swaps, which is its one advantage when writes are expensive.

Insertion sort

Grow a sorted section from the left. Take the next value and slide it leftward past every larger value until it is in place, the way most people sort a hand of cards. On nearly sorted data very little sliding is needed and it runs in close to O(n). That, and its low overhead, is why production sorts switch to insertion sort for small sub-arrays.

Merge sort

Divide and conquer. Split the array in half, sort each half recursively, then merge the two sorted halves by repeatedly taking the smaller front element. Splitting gives log n levels and each level does O(n) merging work, so it is O(n log n) in every case. It is stable and predictable; the cost is O(n) extra memory. It is also the natural choice for linked lists and for data too large to fit in memory.

Quick sort

Also divide and conquer, but the work happens before the recursion. Choose a pivot, then partition the array so everything smaller is on its left and everything larger on its right. The pivot is now in its final position. Recurse on the two sides. On average the partitions are reasonably even and it runs in O(n log n) with excellent constant factors and no extra array.

The weakness is a bad pivot. If the pivot is always the smallest or largest value, as happens with a last-element pivot on already sorted data, each partition removes only one element and the cost becomes O(n²). Choosing a random pivot or the median of three makes that practically impossible.

What real libraries use

  • Python sorted() and list.sort(): Timsort, a hybrid of merge sort and insertion sort that exploits existing runs in the data. Stable.
  • Java: Timsort for objects (stable), dual-pivot quick sort for primitives.
  • JavaScript Array.prototype.sort: stable by specification since ES2019; V8 uses Timsort. Remember that without a comparator it sorts as strings, so [10, 9, 1].sort() gives [1, 10, 9].

In real code, call the built-in sort. Learn these algorithms for the ideas (divide and conquer, partitioning, merging, stability) that reappear throughout algorithm design.

Sorting Algorithms in Python, Java and JavaScript

Every sample below runs as is and prints the results shown in its comments. Switch language with the tabs; your choice is remembered on every page.

def bubble_sort(a):                       # O(n^2), stable, in place
    n = len(a)
    for i in range(n):
        swapped = False
        for j in range(n - i - 1):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:                   # already sorted: stop early
            break
    return a

def selection_sort(a):                    # O(n^2), not stable, in place
    for i in range(len(a) - 1):
        smallest = i
        for j in range(i + 1, len(a)):
            if a[j] < a[smallest]:
                smallest = j
        a[i], a[smallest] = a[smallest], a[i]
    return a

def insertion_sort(a):                    # O(n^2) worst, O(n) if nearly sorted, stable
    for i in range(1, len(a)):
        key, j = a[i], i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

def merge_sort(a):                        # O(n log n) always, stable, O(n) extra space
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:           # <= keeps equal items in order (stable)
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    return merged + left[i:] + right[j:]

def quick_sort(a, lo=0, hi=None):         # O(n log n) average, O(n^2) worst, in place
    if hi is None:
        hi = len(a) - 1
    if lo < hi:
        pivot, i = a[hi], lo
        for j in range(lo, hi):           # Lomuto partition
            if a[j] < pivot:
                a[i], a[j] = a[j], a[i]
                i += 1
        a[i], a[hi] = a[hi], a[i]
        quick_sort(a, lo, i - 1)
        quick_sort(a, i + 1, hi)
    return a

import java.util.Arrays;

public class Sorting {
    static void bubbleSort(int[] a) {                  // O(n^2), stable, in place
        for (int i = 0; i < a.length; i++) {
            boolean swapped = false;
            for (int j = 0; j < a.length - i - 1; j++) {
                if (a[j] > a[j + 1]) { swap(a, j, j + 1); swapped = true; }
            }
            if (!swapped) break;                       // already sorted: stop early
        }
    }

    static void selectionSort(int[] a) {               // O(n^2), not stable, in place
        for (int i = 0; i < a.length - 1; i++) {
            int smallest = i;
            for (int j = i + 1; j < a.length; j++) if (a[j] < a[smallest]) smallest = j;
            swap(a, i, smallest);
        }
    }

    static void insertionSort(int[] a) {               // O(n^2) worst, O(n) if nearly sorted
        for (int i = 1; i < a.length; i++) {
            int key = a[i], j = i - 1;
            while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
            a[j + 1] = key;
        }
    }

    static void mergeSort(int[] a) {                   // O(n log n) always, stable, O(n) space
        if (a.length <= 1) return;
        int[] left = Arrays.copyOfRange(a, 0, a.length / 2);
        int[] right = Arrays.copyOfRange(a, a.length / 2, a.length);
        mergeSort(left);
        mergeSort(right);
        int i = 0, j = 0, k = 0;
        while (i < left.length && j < right.length) a[k++] = left[i] <= right[j] ? left[i++] : right[j++];
        while (i < left.length) a[k++] = left[i++];
        while (j < right.length) a[k++] = right[j++];
    }

    static void quickSort(int[] a, int lo, int hi) {   // O(n log n) average, O(n^2) worst
        if (lo >= hi) return;
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++) {                // Lomuto partition
            if (a[j] < pivot) swap(a, i++, j);
        }
        swap(a, i, hi);
        quickSort(a, lo, i - 1);
        quickSort(a, i + 1, hi);
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

    public static void main(String[] args) {
        int[] data = {38, 27, 43, 3, 9, 82, 10};
        int[] a = data.clone(); bubbleSort(a);              System.out.println(Arrays.toString(a));
        a = data.clone(); selectionSort(a);                 System.out.println(Arrays.toString(a));
        a = data.clone(); insertionSort(a);                 System.out.println(Arrays.toString(a));
        a = data.clone(); mergeSort(a);                     System.out.println(Arrays.toString(a));
        a = data.clone(); quickSort(a, 0, a.length - 1);    System.out.println(Arrays.toString(a));
    }
}
function bubbleSort(a) {                   // O(n^2), stable, in place
  for (let i = 0; i < a.length; i++) {
    let swapped = false;
    for (let j = 0; j < a.length - i - 1; j++) {
      if (a[j] > a[j + 1]) { [a[j], a[j + 1]] = [a[j + 1], a[j]]; swapped = true; }
    }
    if (!swapped) break;                   // already sorted: stop early
  }
  return a;
}

function selectionSort(a) {                // O(n^2), not stable, in place
  for (let i = 0; i < a.length - 1; i++) {
    let smallest = i;
    for (let j = i + 1; j < a.length; j++) if (a[j] < a[smallest]) smallest = j;
    [a[i], a[smallest]] = [a[smallest], a[i]];
  }
  return a;
}

function insertionSort(a) {                // O(n^2) worst, O(n) if nearly sorted, stable
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i - 1;
    while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
    a[j + 1] = key;
  }
  return a;
}

function mergeSort(a) {                    // O(n log n) always, stable, O(n) extra space
  if (a.length <= 1) return a;
  const mid = a.length >> 1;
  const left = mergeSort(a.slice(0, mid)), right = mergeSort(a.slice(mid));
  const merged = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) merged.push(left[i] <= right[j] ? left[i++] : right[j++]);
  return merged.concat(left.slice(i), right.slice(j));
}

function quickSort(a, lo = 0, hi = a.length - 1) {   // O(n log n) average, O(n^2) worst
  if (lo < hi) {
    const pivot = a[hi];
    let i = lo;
    for (let j = lo; j < hi; j++) {        // Lomuto partition
      if (a[j] < pivot) { [a[i], a[j]] = [a[j], a[i]]; i++; }
    }
    [a[i], a[hi]] = [a[hi], a[i]];
    quickSort(a, lo, i - 1);
    quickSort(a, i + 1, hi);
  }
  return a;
}

const data = [38, 27, 43, 3, 9, 82, 10];
for (const sort of [bubbleSort, selectionSort, insertionSort, mergeSort, quickSort]) {
  console.log(sort.name, sort([...data])); // each prints [3, 9, 10, 27, 38, 43, 82]
}

When to use it

Which one to reach for

  • Small or nearly sorted input: insertion sort.
  • Need stability or a guaranteed O(n log n): merge sort.
  • General in-memory sorting, memory matters: quick sort with a good pivot.
  • Anything in production: the language's built-in sort.

Beyond comparison sorts

  • Comparison-based sorting cannot beat O(n log n) in the worst case.
  • When keys are small integers, counting sort and radix sort run in O(n + k) by not comparing at all.

Common mistakes

  • Calling JavaScript's sort() on numbers without (a, b) => a - b.
  • Writing a comparator that returns a boolean instead of a negative, zero or positive number.
  • Assuming quick sort is always O(n log n) while using a fixed first or last pivot on sorted input.
  • Assuming a sort is stable when it is not, then losing an earlier ordering.
  • Using < instead of <= in the merge step, which makes merge sort unstable.

Interview questions

Classic problems built on this topic, with the approach to each. Try them yourself before opening the hint.

Which sorting algorithm would you use, and why?

Usually the built-in one. If pressed: merge sort for stability and guarantees, quick sort for in-place speed, insertion sort for small or nearly sorted data.

Sort an array of 0s, 1s and 2s in one pass.

Dutch national flag: three pointers partition the array into three regions in O(n) time and O(1) space.

Find the k-th largest element without fully sorting.

Quickselect: partition as in quick sort but recurse into only one side. O(n) on average.

Merge overlapping intervals.

Sort by start time, then sweep once, extending the current interval or starting a new one.

Why can no comparison sort be faster than O(n log n)?

There are n! possible orderings and each comparison distinguishes at most two outcomes, so at least log₂(n!) ≈ n log n comparisons are needed.

Frequently asked questions

Which sorting algorithm is the fastest?

For general data, O(n log n) algorithms such as quick sort, merge sort and Timsort. Quick sort is often fastest in memory on average; merge sort and Timsort guarantee O(n log n) and are stable.

What is a stable sorting algorithm?

One that keeps items with equal keys in their original order. Bubble, insertion and merge sort are stable; selection sort and quick sort are not.

What is the difference between merge sort and quick sort?

Merge sort splits first and does its work while merging, always O(n log n), using O(n) extra space. Quick sort does its work while partitioning around a pivot, sorts in place, and is O(n log n) on average but O(n²) in the worst case.
