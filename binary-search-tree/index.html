Binary Search Trees

A binary search tree (BST) is a binary tree with one rule: every key in a node's left subtree is smaller than the node, and every key in its right subtree is larger. That rule turns each comparison into a decision that discards half the tree.

  • Level: Intermediate
  • Read time: 12 min
  • Balanced: O(log n)
  • Worst case: O(n)

What is a binary search tree?

Binary search on a sorted array is fast, but inserting into a sorted array is O(n) because of shifting. A BST gives you the same halving search in a structure that is cheap to modify.

The ordering rule holds at every node, not only the root. To find a key, start at the root: if the key is smaller go left, if larger go right, and repeat. Each step moves one level down, so the cost is the height of the tree. For a balanced tree of a million keys that is about 20 comparisons.

Try it: insert, search, delete

Search for 60 and follow the path. Then press Sorted insert to see what goes wrong without balancing.

How the operations work

Search

Compare with the current node and go left or right until you find the key or run out of tree.

Insert

Search for the key. The empty spot where the search fails is exactly where the new node belongs. New keys always become leaves.

Delete: three cases

  1. Leaf: remove it.
  2. One child: replace the node with its child.
  3. Two children: find the node's in-order successor, the smallest key in its right subtree. Copy that key into the node, then delete the successor (which has at most one child, so it falls under case 1 or 2). The successor is the next key in sorted order, so the ordering rule is preserved. In the visualizer, delete 50 from the starting tree to see it.

Why balance matters

All three operations cost O(h), where h is the height. A BST's shape depends on insertion order. Insert 10, 20, 30, 40, 50 in that order and every node goes to the right of the last: the tree is a linked list of height n − 1 and every operation is O(n).

Self-balancing trees fix this by restructuring with rotations after insertions and deletions so the height stays O(log n):

  • AVL trees keep the heights of the two subtrees of every node within 1 of each other. Strictly balanced, fastest lookups.
  • Red-black trees allow slightly more imbalance in exchange for fewer rotations. Java's TreeMap and TreeSet and C++'s std::map are red-black trees.
  • B-trees store many keys per node and are what database indexes use.

BST or hash table?

A hash table has faster lookups (O(1) on average) but keeps no order. A balanced BST gives O(log n) lookups and sorted iteration, minimum and maximum, the next key above or below a value, and range queries such as "all orders between two dates".

class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None


class BST:
    def __init__(self):
        self.root = None

    def insert(self, key):                # O(h), h = height
        self.root = self._insert(self.root, key)

    def _insert(self, node, key):
        if node is None:
            return Node(key)
        if key < node.key:
            node.left = self._insert(node.left, key)
        elif key > node.key:
            node.right = self._insert(node.right, key)
        return node                       # equal keys are ignored

    def contains(self, key):              # O(h), iterative
        node = self.root
        while node:
            if key == node.key:
                return True
            node = node.left if key < node.key else node.right
        return False

    def delete(self, key):                # O(h)
        self.root = self._delete(self.root, key)

    def _delete(self, node, key):
        if node is None:
            return None
        if key < node.key:
            node.left = self._delete(node.left, key)
        elif key > node.key:
            node.right = self._delete(node.right, key)
        else:
            if node.left is None:         # zero or one child
                return node.right
            if node.right is None:
                return node.left
            successor = node.right        # two children: smallest in right subtree
            while successor.left:
                successor = successor.left
            node.key = successor.key
            node.right = self._delete(node.right, successor.key)
        return node

    def sorted_keys(self):                # in-order traversal
        out = []
        def walk(node):
            if node:
                walk(node.left); out.append(node.key); walk(node.right)
        walk(self.root)
        return out

import java.util.ArrayList;
import java.util.List;

public class BST {
    private static class Node {
        int key; Node left, right;
        Node(int key) { this.key = key; }
    }

    private Node root;

    public void insert(int key) { root = insert(root, key); }       // O(h), h = height

    private Node insert(Node node, int key) {
        if (node == null) return new Node(key);
        if (key < node.key) node.left = insert(node.left, key);
        else if (key > node.key) node.right = insert(node.right, key);
        return node;                                                // equal keys are ignored
    }

    public boolean contains(int key) {                              // O(h), iterative
        Node node = root;
        while (node != null) {
            if (key == node.key) return true;
            node = key < node.key ? node.left : node.right;
        }
        return false;
    }

    public void delete(int key) { root = delete(root, key); }       // O(h)

    private Node delete(Node node, int key) {
        if (node == null) return null;
        if (key < node.key) node.left = delete(node.left, key);
        else if (key > node.key) node.right = delete(node.right, key);
        else {
            if (node.left == null) return node.right;               // zero or one child
            if (node.right == null) return node.left;
            Node successor = node.right;                            // two children
            while (successor.left != null) successor = successor.left;
            node.key = successor.key;
            node.right = delete(node.right, successor.key);
        }
        return node;
    }

    public List<Integer> sortedKeys() {                             // in-order traversal
        List<Integer> out = new ArrayList<>();
        walk(root, out);
        return out;
    }

    private void walk(Node node, List<Integer> out) {
        if (node == null) return;
        walk(node.left, out); out.add(node.key); walk(node.right, out);
    }

    public static void main(String[] args) {
        BST tree = new BST();
        for (int key : new int[]{50, 30, 70, 20, 40, 60, 80}) tree.insert(key);
        tree.delete(50);                                            // root with two children
        System.out.println(tree.sortedKeys());                      // [20, 30, 40, 60, 70, 80]
        System.out.println(tree.contains(60) + " " + tree.contains(50)); // true false
    }
}
class Node {
  constructor(key) { this.key = key; this.left = null; this.right = null; }
}

class BST {
  root = null;

  insert(key) { this.root = this.#insert(this.root, key); }   // O(h), h = height

  #insert(node, key) {
    if (!node) return new Node(key);
    if (key < node.key) node.left = this.#insert(node.left, key);
    else if (key > node.key) node.right = this.#insert(node.right, key);
    return node;                                              // equal keys are ignored
  }

  contains(key) {                                             // O(h), iterative
    let node = this.root;
    while (node) {
      if (key === node.key) return true;
      node = key < node.key ? node.left : node.right;
    }
    return false;
  }

  delete(key) { this.root = this.#delete(this.root, key); }   // O(h)

  #delete(node, key) {
    if (!node) return null;
    if (key < node.key) node.left = this.#delete(node.left, key);
    else if (key > node.key) node.right = this.#delete(node.right, key);
    else {
      if (!node.left) return node.right;                      // zero or one child
      if (!node.right) return node.left;
      let successor = node.right;                             // two children
      while (successor.left) successor = successor.left;
      node.key = successor.key;
      node.right = this.#delete(node.right, successor.key);
    }
    return node;
  }

  sortedKeys() {                                              // in-order traversal
    const out = [];
    const walk = node => { if (node) { walk(node.left); out.push(node.key); walk(node.right); } };
    walk(this.root);
    return out;
  }
}

When to use it

Use a (balanced) BST when

  • You need keys kept in sorted order while inserting and deleting.
  • You need range queries, or floor and ceiling lookups.
  • You need predictable O(log n) worst-case behaviour.

Look elsewhere when

  • You only need exact-match lookups (a hash table is simpler and faster).
  • You only ever need the smallest or largest item (a heap is lighter).

Common mistakes

  • Validating a BST by comparing each node only with its direct children. The rule applies to whole subtrees: pass down an allowed (min, max) range instead.
  • Forgetting the two-children case in delete.
  • Assuming O(log n) for a plain BST fed with sorted data.
  • Not deciding how duplicates are handled.

Interview questions

Classic problems built on this topic, with the approach to each. Try them yourself before opening the hint.

Validate that a binary tree is a BST.

Recurse with a lower and upper bound for each node, or check that the in-order traversal is strictly increasing.

Find the k-th smallest element.

In-order traversal, stopping at the k-th node visited.

Lowest common ancestor in a BST.

Walk from the root: the first node whose key lies between the two targets is the answer.

Convert a sorted array to a balanced BST.

Make the middle element the root and build the left and right halves recursively.

Find the in-order successor of a node.

If it has a right child, the leftmost node of that subtree; otherwise the nearest ancestor for which the node is in the left subtree.

Frequently asked questions

What is the time complexity of a binary search tree?

Search, insert and delete are O(h), where h is the height. That is O(log n) for a balanced tree and O(n) in the worst case for an unbalanced one.

What happens when you insert sorted data into a BST?

Each new key goes to the right of the previous one, producing a tree shaped like a linked list with O(n) operations. Self-balancing trees such as AVL and red-black trees prevent this.

How do you delete a node with two children?

Replace its key with its in-order successor (the smallest key in its right subtree), then delete that successor node.
