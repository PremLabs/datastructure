Big-O Notation

Big-O notation describes how the work an algorithm does grows as its input grows. It lets you compare two solutions without timing them, and it is the first thing an interviewer asks about any code you write.

  • Level: Beginner
  • Read time: 8 min
  • Prerequisites: Loops and functions

What Big-O actually measures

Suppose a function takes 2 milliseconds on 1,000 items. That number says very little: it depends on the machine, the language and what else was running. The useful question is different: if the input becomes ten times larger, how much more work is there? Big-O answers that question.

We count basic steps (comparisons, assignments, array reads) as a function of the input size n, then keep only the part that dominates when n is large. A function that does 3n² + 5n + 20 steps is O(n²): for a million items the n² term is so large that the rest does not matter, and the constant 3 changes the speed but not the shape of the growth.

Two rules cover most cases. Drop constants (O(2n) is O(n)). Drop smaller terms (O(n² + n) is O(n²)).

How to work out the complexity of your code

  1. A single loop over the input is O(n). Two loops one after another are still O(n), because O(n + n) drops the constant.
  2. A loop inside a loop multiplies. Two nested loops over the same input are O(n²).
  3. Halving the problem each step is O(log n). If a loop divides n by two until it reaches one, it runs about log₂ n times.
  4. Recursion: count the calls and the work per call. Merge sort makes log n levels of calls and does O(n) work per level, so O(n log n).
  5. Check what library calls cost. x in list in Python and list.contains(x) in Java are O(n). Calling them inside a loop quietly gives you O(n²).

Space complexity

The same notation describes extra memory. An algorithm that sorts in place uses O(1) extra space; one that builds a second copy of the input uses O(n). Recursion uses stack space too: a recursive function that goes n calls deep uses O(n) memory even if it allocates nothing. Often you trade one for the other, as the two duplicate-finding functions in the code below show: the fast version buys O(n) time by spending O(n) memory on a set.

Best, average and worst case

Big-O is usually quoted for the worst case, because that is the guarantee you can rely on. Quick sort is O(n log n) on average but O(n²) on its worst input. A hash table lookup is O(1) on average but O(n) if every key lands in the same bucket. Amortised cost is a related idea: appending to a dynamic array is occasionally O(n) when it resizes, but averaged over many appends each one costs O(1).

Big-O Notation in Python, Java and JavaScript

Every sample below runs as is and prints the results shown in its comments. Switch language with the tabs; your choice is remembered on every page.

def first_item(items):            # O(1): one step, whatever the size
    return items[0]

def contains(items, target):      # O(n): may look at every item
    for item in items:
        if item == target:
            return True
    return False

def has_duplicate(items):         # O(n^2): every pair is compared
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                return True
    return False

def has_duplicate_fast(items):    # O(n) time, O(n) extra space
    seen = set()
    for item in items:
        if item in seen:
            return True
        seen.add(item)
    return False

def halvings(n):                  # O(log n): n is halved each loop
    steps = 0
    while n > 1:
        n //= 2
        steps += 1
    return steps

print(halvings(1_000_000))        # 19
print(has_duplicate_fast([3, 1, 4, 1]))  # True
import java.util.HashSet;
import java.util.Set;

public class BigO {
    static int firstItem(int[] items) {            // O(1)
        return items[0];
    }

    static boolean contains(int[] items, int target) {  // O(n)
        for (int item : items) {
            if (item == target) return true;
        }
        return false;
    }

    static boolean hasDuplicate(int[] items) {     // O(n^2)
        for (int i = 0; i < items.length; i++) {
            for (int j = i + 1; j < items.length; j++) {
                if (items[i] == items[j]) return true;
            }
        }
        return false;
    }

    static boolean hasDuplicateFast(int[] items) { // O(n) time, O(n) space
        Set<Integer> seen = new HashSet<>();
        for (int item : items) {
            if (!seen.add(item)) return true;
        }
        return false;
    }

    static int halvings(int n) {                   // O(log n)
        int steps = 0;
        while (n > 1) { n /= 2; steps++; }
        return steps;
    }

    public static void main(String[] args) {
        System.out.println(halvings(1_000_000));                     // 19
        System.out.println(hasDuplicateFast(new int[]{3, 1, 4, 1})); // true
    }
}
const firstItem = items => items[0];              // O(1)

function contains(items, target) {                // O(n)
  for (const item of items) {
    if (item === target) return true;
  }
  return false;
}

function hasDuplicate(items) {                    // O(n^2)
  for (let i = 0; i < items.length; i++) {
    for (let j = i + 1; j < items.length; j++) {
      if (items[i] === items[j]) return true;
    }
  }
  return false;
}

function hasDuplicateFast(items) {                // O(n) time, O(n) space
  const seen = new Set();
  for (const item of items) {
    if (seen.has(item)) return true;
    seen.add(item);
  }
  return false;
}

function halvings(n) {                            // O(log n)
  let steps = 0;
  while (n > 1) { n = Math.floor(n / 2); steps++; }
  return steps;
}

console.log(halvings(1_000_000));                 // 19
console.log(hasDuplicateFast([3, 1, 4, 1]));      // true

Common mistakes

  • Treating Big-O as speed. An O(n²) algorithm can beat an O(n log n) one on small inputs because its constant factors are smaller. That is why real sort implementations switch to insertion sort for short runs.
  • Forgetting hidden loops. String concatenation in a loop, list.insert(0, x), array.shift() and in on a list are all O(n) each time.
  • Ignoring recursion depth when stating space complexity.
  • Using one variable for two different inputs. Comparing every item of list A with every item of list B is O(a × b), not O(n²).

Interview questions

Classic problems built on this topic, with the approach to each. Try them yourself before opening the hint.

What is the time complexity of two nested loops where the inner loop runs from i to n?

Still O(n²). The total is n(n−1)/2 steps, and constants are dropped.

Why is binary search O(log n)?

Each comparison halves the remaining range, and you can halve n only log₂ n times before one element is left.

What does amortised O(1) mean?

Any single operation may be expensive, but a sequence of n operations costs O(n) in total, so the average per operation is constant.

Is O(n + m) the same as O(n)?

Only if m is known to be no larger than n. With two independent inputs, keep both.

Frequently asked questions

Is Big-O the same as the running time?

No. Big-O describes how the running time grows as the input grows. It ignores constant factors and hardware, so it tells you which algorithm scales better, not how many milliseconds either one takes.

What is the difference between O(n) and O(log n)?

O(n) work grows in step with the input: double the data, double the work. O(log n) work grows by one step each time the data doubles, so a million items need about 20 steps.

Do I need maths to learn Big-O?

Very little. Counting loops, recognising halving and knowing that nested loops multiply will cover most code you write or read.
